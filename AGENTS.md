## Learned User Preferences

- British spelling in user-facing plugin messages and documentation.
- Use TDD for domain logic: write failing tests first, then implement until `mvn test` passes.
- Run `mvn package` and provide the JAR path when the user intends to deploy to the game server.
- Use grill-me or grill-with-docs for major feature design; ask one question at a time with a recommended answer.
- Do not create git commits or pushes unless explicitly requested.
- Prefer tracer-bullet vertical slices over large single implementations.
- Minimise diff scope and match existing Java/Maven conventions in the repo.
- Use caveman mode (terse responses) when the user invokes `/caveman`; resume only after they say "stop caveman" or "normal mode".
- Capture agreed domain terms in `CONTEXT.md` during grill-with-docs sessions (glossary only, no implementation detail).
- Do not implement anti-AFK detection for life events.

## Learned Workspace Facts

- Private Bukkit plugin for **Paper** 1.21.x / MC 26.x (Java 21); compiles against Spigot API; build with `mvn test package`.
- Deploy artefact: `target/kingdom-0.1.0-SNAPSHOT.jar` to the server `plugins/` folder; MC 26.1.2 bundle in `deploy/plugins-26.1.2/` (WorldEdit 7.4.3, WorldGuard 7.0.17); GitHub repo `https://github.com/mrlemoos/kingdom`; upload JARs via `scp -P 2224 … admin@srv1753557.hstgr.cloud:/plugins/`.
- Admin-defined kingdoms; players join once via `/kingdom join`; only OP can move members.
- Noble titles are admin-assigned with fixed slots; Knight has unlimited slots; hierarchy sort in `/kingdom info`; title ladder: King/Queen, Prince/Princess (2 slots, yellow prefix, −3% default tax), Premier, Speaker, Duke/Duchess, Lord/Lady, Count/Countess, MP, Knight/Dame. Elections fill 8 Commons seats (up to 4 player MPs + villager professions, with **[MP] Citizen** backfill when professions run short); OP cannot assign MP. **Premier** is elected by seated player MPs after a general election; when no player MPs are seated, a **Premier villager** is chosen from profession MPs (highest election-scan count; Citizen backfill ineligible), tables inaugural FISCAL then BUDGET bills via realm-handled Commons divisions two in-game days after the general election closes, and shows a `[Premier]` nametag; monarch still grants royal assent in Lords. Villager MPs claim territory villagers and release them to stored origin with default despawn and combat behaviour when elections end; all villagers including seated villager MPs are damageable. **`/resign`** lets seated Premier or player MPs offer to leave; villager MP/Premier resignation uses the same pending-approval flow by targeting the seated villager entity (seated MP, Premier, or Speaker may offer). Office-holder keeps full parliamentary powers until King/Queen—or Prince when no monarch is seated—accepts; a **resignation letter** (paper) is delivered to the Crown inventory on offer (on login if offline); right-click opens the review GUI with Lords hub fallback; rejection leaves them in office; one pending offer per kingdom. Premier parliamentary actions are blocked during active elections. Acceptance triggers a Premier election or Commons by-election as appropriate.
- Noble chat/tab/nametag prefixes are bold uppercase with per-rank colours; citizens have no prefix; villager MP nametags use the same grey `[MP] ` prefix as player MPs (Premier villager uses `[Premier]` in Premier rank colour); other territory villagers show profession nametags (**Commoner** when none), refreshing on profession change. Ordinary territory villagers (not seated MPs or Treasury Lords) inside a kingdom's linked WorldGuard region are protected from vanilla despawning; protection is position-scoped and reverts when they leave; reconciled on startup sync, chunk load, villager spawn, and a 60-second periodic sweep.
- Kingdom persistence in `plugins/Kingdom/data.yml` (members, teleports, parliament, elections); economy state in `plugins/Kingdom/economy.yml`.
- Full Corona economy with **realm wealth** (treasury Corona plus active productive **villager wallet** balances plus valued material blocks and beacon/conduit/lodestone estates in linked WorldGuard territory; informational only) and Westminster-style Parliament (Commons divisions, Lords assent, registrar Acts on bookshelves); **villager economy** credits daily GDP to productive-villager wallets (base-rate income tax to treasury), runs config profession trade-graph settlements (commerce tax to treasury), freezes wallets when not productive, escheats long-frozen balances, and keeps seated villager MPs economically active as profession proxies; player villager-trade rewards stay decoupled; `/kingdom info` shows villager-wallet aggregates; **mints** spawn a **Lord of the Treasury** villager for nugget deposit/withdraw—King or Queen may place one at a territory lectern via `/kingdom mint place` (no Parliament budget; mint cap still applies), or via Parliament supply bill; King, Queen, or OP `/kingdom mint despawn` removes the aimed Lord of the Treasury or the nearest mint; `/kingdom list` ranks by realm wealth; villager wallets and territory block counts persist in `economy.yml`; domain glossary in `CONTEXT.md`.
- Plugin `/tp` overrides vanilla player/coordinate teleport (`~` supported); per-kingdom named checkpoints in `data.yml` (OP `checkpoint create`, members `/tp <name>`).
- WorldGuard is a soft dependency via `WorldGuardBridge` (reflection); territory linked with `/kingdom setregion` and `/kingdom setworld`; wilderness income chiefly applies in Nether/End.
- OP `/kingdom treasury credit <kingdom> <amount>` for testing treasury balance; no block, PvP, or build enforcement yet; domain logic in testable Java services, Bukkit layer verified manually on server.
- Agreed **planned** command migration to Incendo Cloud v2 (hybrid builders + annotations, big-bang cutover): Cloud handles syntax/usage errors only; domain `KingdomResult`/`EconomyResult` messages unchanged; use `LegacyPaperCommandManager` with Brigadier when available.
